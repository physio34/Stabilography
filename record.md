# adVestibular — Система стабилографии

Программа для записи и анализа данных стабилограммы с платформы **MERA Stabilo** (стабилоплатформа,.used в отоневрологической практике для оценки вестибулярного аппарата).

## Зависимости

- Python 3.8+
- numpy
- pandas
- matplotlib (для `mera_stabilo.py`)
- dearpygui (для `main_pygui.py`)

## Запуск

```bash
# Matplotlib-версия
python mera_stabilo.py live

# Dear PyGui-версия
python main_pygui.py live
```

### Основные аргументы

| Аргумент | Описание |
|---|---|
| `--device /dev/input/eventN` | Путь к устройству (иначе авто-поиск) |
| `--axes axes.json` | JSON-конфиг осей и калибровки |
| `--rate 50` | Частота дискретизации, Гц |
| `--duration 30` | Авто-остановка через N секунд (0 = бесконечно) |
| `--out stabilo.csv` | Выходной CSV-файл |
| `--plot stabilo.png` | Выходной PNG-файл |

### Пример конфигурации осей (`axes.json`)

```json
{
  "xcode": 0,
  "ycode": 1,
  "rate": 50,
  "contact_timeout": 0.5,
  "calibrate": 2.0,
  "scale_x": 1.0,
  "scale_y": 1.0,
  "offset_x": 0.0,
  "offset_y": 0.0,
  "device": null,
  "max_x": null,
  "max_y": null
}
```

## Алгоритм выделения блоков для перевода

Под «блоками для перевода» понимаются участки сырых событий Linux input (`input_event`), которые преобразуются в стабилографические данные. Алгоритм состоит из следующих этапов:

### 1. Обнаружение устройства

Функция `discover_device()`:

1. Перечисляет директории `/sys/class/input/eventN/device/name`.
2. Ищет устройство, имя которого содержит строку `"MERA"`.
3. Возвращает путь `/dev/input/eventN` или `None`, если устройство не найдено.

### 2. Валидация устройства (отсечение тачпадов)

Функция `is_likely_stabilo_platform()`:

1. Читает битовую маску поддерживаемых ABS-кодов из `capabilities/abs`.
2. Если количество кодов > 5 — это тачпад, не стабилоплатформа.
3. Если среди кодов присутствуют multитач-коды (47–63) — также отсеивается.

### 3. Чтение сырых событий (фоновый поток)

Класс `Device`:

1. Открывает `/dev/input/eventN` в режиме `O_RDONLY | O_NONBLOCK`.
2. Фоновый поток опрашивает файловый дескриптор через `select.poll()`.
3. Читает пакеты событий по 64 структуры `input_event` (формат `"llHHi"`: `timeval + type + code + value`).
4. Фильтрует только события типа `EV_ABS` (type = 3).
5. Для каждого события проверяет:
   - Код входит в список допустимых (`valid_codes` из `capabilities`).
   - Значение не превышает допустимый диапазон (≤ 65535).
6. Сохраняет кортеж `(timestamp, code, value)` в кольцевой буфер `deque(maxlen=400000)`.

### 4. Автоопределение осей

Функция `auto_detect_axes()`:

1. В течение окна калибровки (по умолчанию 2 с) собирает все ABS-коды.
2. Если коды 0 и 1 присутствуют — используются как X и Y.
3. Иначе сортирует коды по дисперсии значений и берёт два кода с наибольшей дисперсией.

### 5. Семплирование (извлечение блоков)

Функция `sample_once()`:

1. Вызывается с частотой дискретизации (по умолчанию 50 Гц).
2. Считывает текущие значения X и Y из `Device.get()`.
3. Применяет линейное преобразование:
   - `x = xraw × scale_x + offset_x`
   - `y = yraw × scale_y + offset_y`
4. Определяет контакт стопы с платформой:
   - Если `(текущее_время - время_последнего_события) < contact_timeout` → `contact = 1.0`
   - Иначе → `contact = 0.0`
5. Сохраняет кортеж `(относительное_время, x, y, contact)`.

### 6. Вычисление метрик

Функция `compute_metrics()`:

1. Отбирает только точки с контактом (`contact > 0.5`).
2. Вычисляет:
   - `n` — количество отсчётов
   - `T` — длительность записи
   - `xm`, `ym` — среднее положение центра давления
   - `sx`, `sy` — стандартное отклонение
   - `maxdev_x`, `maxdev_y` — максимальное отклонение от среднего
   - `range_x`, `range_y` — размах
   - `L` — длина траектории: `Σ√(Δx² + Δy²)`
   - `vel` — средняя скорость качания: `L / T`
   - `rms` — среднеквадратичное отклонение от центра

### 7. Экспорт результатов

- **CSV**: `t_rel_s`, `x`, `y`, `contact` — сырые данные по отсчётам.
- **PNG**: стабилограмма (траектория ЦД) + временные ряды X/Y.
- **Текст**: сводка стабилографических показателей.
